# ADR-0002: identity_recheck는 방어 계층이다 — 범위 축소의 실차단은 게이트 책임

- 상태: Accepted · 2026-08-11 · 커밋 efa9110 (Track 2a)

## 맥락

identity_recheck(Σ기여 == Δ전체)는 registry §3.5가 "전체 시스템에서 가장 싼
결정론적 검사"로 지정한 '데이터 확인' 라벨의 초석인데, **두 번 연속 항진식으로
판명**됐다:

1. v0.1: total을 세그먼트 집계의 합으로 계산해 같은 숫자를 두 번 더해 비교 —
   구조적으로 실패 불가 (방법론 패널 발견: region 범위 축소 -70u가 전사 Δ로
   라벨돼도 통과).
2. 1차 수리판: "독립 총계"가 세그먼트 집계와 같은 루프·같은 sel 필터를 공유
   + 선행 커버리지 게이트가 검사 범위의 상위집합을 검사(섀도잉) — 적대 검증
   84개 조합 프로브에서 발화 0회.

교훈: **같은 루프·같은 필터를 공유하는 검산은 검증이 아니다.** 그리고 도달
가능성이 게이트 서열에 의해 결정되는 검사는 그 서열까지 문서화해야 한다.

## 결정

1. 비교 기준은 `raw_scope_total` — 분해·집계 로직과 **코드 경로가 분리된**
   원시 행 스캔(차원값 검사도 세그먼트 분기도 없음).
2. identity_recheck의 지위는 **방어 계층(defense-in-depth)**으로 정직하게
   재라벨한다: 선행 게이트가 전부 통과한 정상 경로에서는 산술적으로 실패할 수
   없으며, 역할은 조립 경로와 스캔 경로가 갈리는 구현 결함의 검출이다.
   **'데이터 확인' 라벨의 근거로 이 검사를 단독 인용하지 말 것.**
3. 범위 침묵 축소의 실제 차단은 게이트 4종이 담당한다:
   - `scope_declared` (양방향): 분해 차원의 applies_to가 within으로 제약되어야
     하고, within 키 자신의 applies_to도 함께 선언되어야 함. 미지 차원은
     크래시가 아니라 실패 검사(합 타입 §3.4 보존).
   - `mece_runtime_coverage`: estimand 범위(applies_to 전 키 + within)로 좁힌
     축 값 커버리지.
   - `partition_coverage`: 분해 축이 아닌 파티션 전 차원의 값 커버리지 —
     어떤 축을 물었든 같은 원장이면 같은 게이트가 선다.
   - `coverage_residual`: 선행 게이트가 놓친 오염의 결정론적 잔차 검출기
     (독립 총계 − 선언값 집계 합).

같은 클래스의 결함을 형제 연산자에도 이식 수리: plan_gap(계획 밖 채널 실적
침묵 탈락 → out_of_domain), vrm_lite(NULL 주문 0 흡수 → suspended),
event_overlap_scan(공유 차원 없는 쌍의 가짜 중첩 → 실측 교집합 필터).

## 결과

- 적대 프로브 전 조합 재현 통과, v0 회귀 무결(팩트 시트 전 세그먼트 일치).
- 검사의 "주장"과 "집행"의 분리가 교리화됨: 라벨의 근거는 도달 가능한
  게이트이지, 도달 불가능한 검산이 아니다.

## 재검토 조건

spec→SQL 컴파일 도입 시 raw_scope_total의 독립성(별도 쿼리 경로)을 재확보할 것.
